پورتال جذب و استخدام میلان پارس

راهنمای استقرار در محیط اجرا

از محیط توسعه تا سرور واقعی — با همهٔ مواردی که باید سرویس، متغیر محیطی یا تصمیم عملیاتی بدانید.

این سند بر اساس خواندن واقعی کد این مخزن نوشته شده، نه فرض. هر جا چیزی در کد آماده نبوده، با نشان «بازبینی لازم» علامت‌گذاری شده — آن‌ها را قبل از اولین استقرار حل کنید.
۰۰

تصویر کلی: چه چیزهایی باید اجرا شوند

سرویسچیستالزامی؟
webDjango (WSGI: gunicorn + Nginx)حتماً
dbPostgreSQL 16حتماً
workermanage.py run_worker — اسکن رزومهٔ آپلودشدهحتماً
clamavسرویس ClamAV برای اسکن فایلحتماً

چرا worker حتماً لازم است

فرم ثبت درخواست رزومه را آپلود می‌کند و بعد تا scan_status فایل clean نشود، ثبت نهایی انجام نمی‌شود (pollUploadStatus در candidate_apply.js). خودِ اسکن جدا از درخواست وب انجام می‌شود: run_worker کار را از جدول BackgroundJob با SELECT … FOR UPDATE SKIP LOCKED برمی‌دارد.

اگر worker بالا نباشد: هر متقاضی پیام «بررسی فایل بیش از حد انتظار طول کشید» می‌بیند و هیچ درخواستی ثبت نمی‌شود. این حالت هنگام ساخت همین سند عملاً بازتولید شد — بدون worker، دکمهٔ ثبت نهایی هیچ پاسخی نمی‌داد.

شمارنده‌های محدودسازی نرخ (ExportRateCounter، StaffLoginRateCounter، TrackingLookupRateCounter) شمارندهٔ دیتابیسی هستند و در همان درخواست وب به‌روز می‌شوند؛ نه Redis لازم است، نه Celery.

۰۱

پیش‌نیاز سرور

Python 3.12 (تصویر پایهٔ docker/Dockerfile)، PostgreSQL 16، و Nginx یا پراکسی معکوس معادل برای TLS و فایل‌های استاتیک.

۰۲

تنظیمات تولید

config/settings/prod.py این‌ها را فعال می‌کند و اگر کلید راز پیش‌فرض بماند، اجرا را متوقف می‌کند:

DEBUG = False
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_SSL_REDIRECT = True      # ← یعنی حتماً باید پشت HTTPS باشید
SECURE_HSTS_SECONDS = 31536000

یعنی قبل از اولین درخواست، گواهی TLS و پراکسی معکوس باید آماده باشد، وگرنه کل ترافیک HTTP به HTTPS ریدایرکت می‌شود.

متغیرهای محیطی

متغیرتوضیحنکته
DJANGO_SETTINGS_MODULEconfig.settings.prodپیش‌فرض پروژه dev است
DJANGO_SECRET_KEYکلید رازاگر پیش‌فرض بماند، اجرا بالا نمی‌آید
DJANGO_ALLOWED_HOSTSدامنهٔ واقعی، با کامابدون آن همهٔ درخواست‌ها 400 می‌گیرند
POSTGRES_*اتصال دیتابیس_HOST پیش‌فرض db
CLAMD_HOST / CLAMD_PORTآدرس ClamAVپیش‌فرض clamav:3310

قالب در .env.example هست. هیچ‌وقت .env واقعی را در گیت نگذارید — در .gitignore هست.

۰۳

گام‌به‌گام

گام ۱ — دیتابیس

PostgreSQL 16 بسازید. برای جداسازی نقش migrate از runtime به docs/operations/db-roles.sql مراجعه کنید.

بازبینی لازم: فهرست جدول‌های db-roles.sql با اسکیمای فعلی هم‌خوان نیست — جدول‌های حذف‌شدهٔ OTP/MFA (candidates_otpchallenge، otp_totp_totpdevice، accounts_staffrecoverycode، candidates_otpratecounter) هنوز در آن هستند و جدول جدید candidates_trackinglookupratecounter در آن نیست. پیش از اعمال روی محیط واقعی، فهرست را از روی جداول واقعی بازبینی کنید.

گام ۲ — کد و وابستگی‌ها

git clone <repo> /srv/reqruitment
cd /srv/reqruitment
python3.12 -m venv .venv
.venv/bin/pip install -r requirements/base.txt
فقط base.txt، نه dev.txt. docker/Dockerfile فعلی dev.txt را نصب می‌کند (pytest، playwright، locust…) که برای تولید مناسب نیست.

gunicorn در هیچ‌کدام از دو فایل requirements نیست. باید جداگانه نصب و پین شود: 
.venv/bin/pip install gunicorn

گام ۳ — متغیرهای محیطی

cp .env.example .env
# مقادیر واقعی را جایگزین کنید: کلید راز، دامنه، اعتبارنامهٔ دیتابیس

.env خودکار خوانده نمی‌شود. هیچ load_dotenv یا env_file در کد نیست؛ متغیرها باید در محیط شل یا سرویس تعریف شوند — EnvironmentFile= در systemd، یا env_file: در Docker (که docker-compose.yml انجام می‌دهد).

گام ۴ — مایگریشن

export DJANGO_SETTINGS_MODULE=config.settings.prod
.venv/bin/python manage.py migrate

اگر دیتابیس از نسخهٔ قدیمی با is_published ارتقا می‌یابد، مایگریشن jobs.0002_preflight_job_status_mapping عامداً متوقف می‌شود اگر ردیفی با ترکیب تأییدنشده داشته باشد، و راه‌حل را در پیام خطا می‌گوید. جزئیات در docs/operations/migrations.md.

گام ۵ — اولین حساب ادمین

هیچ کاربری پیش‌فرض ساخته نمی‌شود (عمدی). اولین hr_manager را بسازید:

.venv/bin/python manage.py createsuperuser_staff --username admin --role hr_manager

رمز تعاملی پرسیده می‌شود. نقش را از همان ابتدا hr_manager بدهید تا بتوانید بقیهٔ کارکنان را از پنل «مدیریت کاربران» بسازید.

گام ۶ — فایل‌های استاتیک

.venv/bin/python manage.py collectstatic --noinput
whitenoise نصب نیست و Django در DEBUG=False فایل استاتیک را سرو نمی‌کند. Nginx باید staticfiles/ را سرو کند، وگرنه صفحهٔ سفید بدون CSS/JS می‌گیرید.
location /static/ {
    alias /srv/reqruitment/staticfiles/;
}

گام ۷ — اجرای web

.venv/bin/gunicorn config.wsgi:application \
  --bind 127.0.0.1:8000 \
  --workers 3

گام ۸ — اجرای worker

.venv/bin/python manage.py run_worker

این فرمان حلقهٔ بی‌پایان است و باید به‌صورت سرویس مدیریت‌شده اجرا شود تا اگر کرش کرد دوباره بالا بیاید:

[Unit]
Description=Reqruitment scan worker
After=network.target postgresql.service

[Service]
WorkingDirectory=/srv/reqruitment
EnvironmentFile=/srv/reqruitment/.env
ExecStart=/srv/reqruitment/.venv/bin/python manage.py run_worker
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

گام ۹ — ClamAV

سرویس ClamAV را بالا بیاورید و CLAMD_HOST/CLAMD_PORT را تنظیم کنید. اولیه‌سازی دیتابیس ویروس چند دقیقه طول می‌کشد و در آن بازه اسکن‌ها scan_failed می‌شوند — عمداً fail-closed، نه «clean».

۰۴

کارهای دوره‌ای (cron)

این‌ها خودکار نیستند و هر کدام باید به cron یا systemd timer وصل شوند.

کاردستورهر چند وقت

اعمال سیاست نگهداریmanage.py enforce_retentionماهانه

enforce_retention به‌طور پیش‌فرض هیچ کاری نمی‌کند چون RETENTION_OPERATIONAL_ENABLED=False است — عمدی. برای فعال‌سازی، فقط بعد از تصمیم صریح ذی‌نفع روشنش کنید. سوابق حسابرسی (AuditEvent) هرگز حذف نمی‌شوند.
0 2 * * *  cd /srv/reqruitment && set -a && . ./.env && set +a && .venv/bin/python manage.py cleanup_uploads >> /var/log/reqruitment/cleanup.log 2>&1
0 3 * * *  cd /srv/reqruitment && set -a && . ./.env && set +a && ./scripts/backup.sh >> /var/log/reqruitment/backup.log 2>&1
